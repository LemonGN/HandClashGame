# 碰手游戏

一个双人回合制「碰手」游戏的可视化实现，包含两部分：

- **Python 求解器**：穷举全部合法局面，计算每方在「自己最优、对方随机」假设下的胜率，并导出为 JSON。
- **网页版对战**：单文件 HTML，内嵌完整状态表，可人机对战，并把状态空间渲染成可交互的树状图，实时查看每个局面的胜率。

## 游戏规则

- 双方各有两只手，初始点数均为 `1`。
- 轮到一方时，选择自己的一只手（攻击手）和对方的一只手（目标手）。
- **对方目标手的点数会加到自己攻击手上**，达到或超过 `10` 记为 `10`（称为「满」或「完成」）。
- 值为 `10` 的手不能再用于攻击，也不能再被选为目标。
- 先让两只手都达到 `10` 的一方获胜。
- `A` 为先手，`B` 为后手，双方交替行动。

> 注意：这是「把对方点数加到自己手上」的玩法变体，不是把点数加到对方手上。

示例：A 用手 `1` 碰 B 的手 `3`，A 的这只手变为 `4`。

## 功能特性

- 开始前可选择执先手 `A` 或后手 `B`，以及电脑策略（随机 / 最优）。
- 手牌图片随点数变化，满手高亮；电脑行动时高亮攻击手与目标手。
- 状态树展示每个局面的双方手牌、行动方以及 `A_p` / `B_p` 胜率。
- 点击节点可展开 / 折叠后续分支；绿色高亮表示当前局面与已走路径。
- 人类回合时，可直接点击树中子节点上的「▶ 选择」按钮落子。
- 画布支持拖拽平移、滚轮缩放、双指缩放、适应屏幕、重置视图。
- 棋盘与状态树之间的分隔条可拖动；内置玩法说明弹窗；适配移动端。
- 无第三方依赖，直接打开 HTML 即可运行。

## 目录结构

```text
.
├── test.py        # 求解器：构建状态空间、计算胜率、导出 JSON、可选命令行对局
├── test.html      # 网页版（HTML / CSS / JS / 状态数据全部内嵌）
└── hand_pic/      # 手牌图片 hand1.jpg ~ hand10.jpg，对应点数 1~10
```

## 快速开始

### 直接打开（推荐）

双击 `test.html`，用 Chrome / Edge 等现代浏览器打开即可。状态数据已内嵌在 HTML 中，不需要启动服务器，也不需要 `data.json`。

### 通过本地服务器打开（可选）

```bash
# Node.js
npx http-server -p 8080 .

# 或 Python 3
python -m http.server 8080
```

然后访问 <http://localhost:8080/test.html>。

### 开始对局

1. 选择身份（先手 A / 后手 B）和电脑策略（随机 / 最优）。
2. 点击「开始游戏」。
3. 轮到你时，先点击自己一只未满的手，再点击对方一只未满的手。
4. 可在下方状态树中点击节点展开分支，或点击子节点上的「▶ 选择」直接行动。
5. 拖动画布、滚轮缩放，查看整张状态图。

## 数据与算法

### 状态表示

一个局面由行动方和四只手的点数唯一确定：

```text
(turn, A1, A2, B1, B2)

turn = 0  # A 行动
turn = 1  # B 行动
Ai/Bi ∈ [1, 10]，10 表示该手已完成
```

JSON 中的键格式为 `"turn:A1,A2,B1,B2"`，例如 `"0:1,1,1,1"` 表示 A 先手的初始局面。

### 动作编码

`childs` 是长度为 4 的数组，下标含义如下（`atk` 为行动方的手，`def` 为对方的手）：

```text
idx = 2 * atk_idx + def_idx

0 -> 攻击方手1 碰 对方手1
1 -> 攻击方手1 碰 对方手2
2 -> 攻击方手2 碰 对方手1
3 -> 攻击方手2 碰 对方手2
```

非法动作为 `null`。

### 胜率定义

- `A_p`：A 采用最优策略、B 采用**随机策略**时，A 当前局面的获胜概率。
- `B_p`：B 采用最优策略、A 采用**随机策略**时，B 当前局面的获胜概率。

两个概率建立在不同的策略假设上，因此通常**不满足** `A_p + B_p = 1`。

### 回溯公式

```text
终局：
  A 双手均为 10  ->  A_p = 1, B_p = 0
  B 双手均为 10  ->  A_p = 0, B_p = 1

A 行动节点：
  A_p = max(所有合法子节点的 A_p)    # A 选最优
  B_p = mean(所有合法子节点的 B_p)   # B 随机

B 行动节点：
  A_p = mean(所有合法子节点的 A_p)   # A 随机
  B_p = max(所有合法子节点的 B_p)    # B 选最优
```

`mean` 只对合法子节点求平均。

### 实现思路

- `test.py` 使用记忆化 DFS：以 `state[turn][a1][a2][b1][b2]` 保存已创建的节点，同一局面只计算一次。
- 每次行动只会让行动方的手值增加，手值不会下降，因此状态图无环，可安全地递归求解。
- 相同局面可能通过不同路径到达，所以状态空间是一个 DAG（有向无环图），但界面上以树的形式展开。
- `WIN = 10` 时共 **9506** 个状态（含行动方区分）、**120** 个终局状态。
- 初始局面 `A[1,1] vs B[1,1]`、A 先手：`A_p = 0.9921875`，`B_p = 1.0`。

### 数据格式

`test.html` 中的 `window.DATA` 形如：

```json
{
  "0:1,1,1,1": {
    "A_p": 0.9921875,
    "B_p": 1.0,
    "childs": ["1:2,1,1,1", "1:2,1,1,1", "1:1,2,1,1", "1:1,2,1,1"]
  }
}
```

`childs` 中可能出现重复的键，这是正常的：不同的落手方式可能到达同一个局面。

## 重新生成数据

`test.html` 里的状态表是 `test.py` 生成时的快照。修改规则或 `WIN` 后，需要重新生成并嵌入：

1. 修改 `test.py` 顶部的 `WIN` 常量。
2. 运行：

   ```bash
   python test.py
   ```

   程序会打印节点数、终局数和根节点胜率，并生成 `data.json`。

3. 在 `test.html` 中搜索 `window.DATA = `，把那一整行替换为：

   ```js
   window.DATA = <data.json 的完整内容>;
   ```

4. 同时确认 `test.html` 中的 `const WIN = 10;` 与求解器一致，并保证 `hand_pic/` 覆盖 `1 ~ WIN` 的所有点数图片。

> 网页运行时并不会读取 `data.json`，它只是导出结果。页面中「加载 data.json 失败」的提示是旧文案，实际加载的是内嵌的 `window.DATA`。

## 命令行对局（可选）

`test.py` 的 `__main__` 中保留了 `play_game(root)` 调用。取消注释后运行 `python test.py`，即可在终端中与电脑对局：

```python
# 进入对局
play_game(root)
```

命令行模式同样支持选择先后手，以及电脑随机 / 最优策略。

## 技术实现

- **求解器**：Python 3，仅使用标准库 `sys` / `random` / `json`。
- **前端**：原生 HTML + CSS + JavaScript，SVG 绘制状态树，无任何外部依赖。
- **数据规模**：约 9.5K 个状态，内嵌 JSON 约 0.9 MB（整个 HTML 约 1 MB）。
- **界面**：深色主题，支持桌面鼠标与移动端触控操作。

## 已知说明

- `test.html` 内嵌的 `WIN` 与状态表必须来自同一份求解结果；只改其中一处会导致界面与数据不一致。
- 状态树按局面键复用节点。当同一局面经不同路径出现时，多个分支会共用同一个方块，布局上可能出现空位或连线重叠。
- 本项目的「攻击」规则是把对方点数加到**自己**手上；若要改成常见的「加到对方手上」规则，需要同时修改 `test.py` 的 `build` 逻辑和 `test.html` 的 `applyHit`，然后重新生成数据。
