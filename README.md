# 碰手游戏（Hand Clash）

双人回合制碰手游戏，支持人机对战、自定义开局、回退，以及显示胜率的交互式 SVG 状态图。Python 求解器计算全部 20,000 个局面，浏览器按表选择电脑走法。

## 运行

直接用 Chrome / Edge 打开 `index.html`，无需安装依赖或启动服务器。页面使用普通脚本加载本地数据，支持 `file://`。分发时需复制整个项目的 `index.html`、`styles/`、`js/`、`data/`、`hand_pic/`，不能只复制 HTML。

也可以在项目根目录运行：

```bash
python -m http.server 8080
```

然后访问 `http://localhost:8080/`。

## 玩法

1. 选择先手 A / 后手 B，以及电脑的随机 / 最优策略。
2. 开始前可点击四只手，循环调整点数（1 → 2 → … → 10 → 1）；状态图会同步更新。
3. 点击「开始游戏」。轮到你时，先选自己的手，再选对方的手；也可展开当前状态图，点击子节点的「▶ 选择」。
4. 点击「回退」恢复到上一次自己的决策前；电脑行动中和结束后也能回退。
5. 点击「重新开始」回到可编辑开局，保留玩家身份和电脑策略。

规则：对方的点数加到**自己的攻击手**上，达到或超过 10 记为 10。满手不能攻击，也不能被选作目标。先让自己的两只手都满的一方获胜，A 先行。自定义开局已经满足获胜条件时立即结束；双方同时满时按求解器约定判 A 胜。

## 开发约定

前端采用普通脚本和立即执行函数，每个模块仅通过 `window.HandClash` 暴露明确的接口。这样保留本地直接打开的能力，也避免把所有函数放进全局作用域。没有构建步骤，也没有前端运行时依赖。

- 修改游戏规则或策略：先改 `js/rules.js`，同步 Python 求解器，再重新生成数据并验证。
- 修改对局流程：改 `js/game.js`。棋盘点击、树节点选择和 AI 最终都经过同一个落子函数。
- 修改棋盘外观或高亮：改 `js/board.js` 和 `styles/app.css`。
- 修改状态图布局：改 `js/layout.js`；修改渲染和点击交互：改 `js/tree.js`；修改视角操作：改 `js/view.js`。
- 增加界面事件：放在 `js/controls.js`，由 `js/app.js` 统一初始化。
- 游戏数据在启动时转存为 `HandClash.state.table`；对局和视图分别保存在 `HandClash.state.GAME`、`HandClash.state.VIZ`。
- 重开与回退会递增对局会话编号，并取消待执行的 AI 计时器；异步动画完成时核对编号，避免上一局的动作修改当前局面。
- 回退仅保存人类决策前的快照，恢复手牌、玩家设置、展开集合、路径和平移缩放。结束局面无需额外入栈。

棋盘按点数加载 `hand_pic/hand1.jpg` 到 `hand_pic/hand10.jpg`。替换照片时保留这些文件名即可；数字角标、满手标记和操作高亮仍然保留。

### 紧凑状态图布局

布局先合并重复局面和同一对节点间的重复动作边，再按拓扑顺序分层，保证所有连线向下。每一层根据父节点位置排序，以父节点的平均位置作为目标；通过相邻块合并计算最接近目标、同时满足最小间距的横坐标。

上层坐标不依赖子树宽度，因此展开更深的分支不会再反向撑开根节点下一层。节点宽度由 `js/core.js` 的 `NODE_W` 控制，同层最小空隙由 `H_GAP` 控制。一个局面只占一个位置；若不同动作到达同一局面，会共用节点，选择按钮使用第一个对应的合法动作。为保持紧凑，父节点不强制位于全部子节点的正中间，多个分支共享局面时连线仍可能交叉。

## 数据与算法

局面键是 `"turn:A1,A2,B1,B2"`，其中 `turn=0` 表示 A 行动，`turn=1` 表示 B 行动，手值范围为 1～10。例如：

```json
{
  "0:1,1,1,1": {
    "A_p": 0.9921875,
    "B_p": 1.0,
    "childs": ["1:2,1,1,1", "1:2,1,1,1", "1:1,2,1,1", "1:1,2,1,1"]
  }
}
```

`childs` 的四个位置依次对应「自己的手 1 碰对方手 1」「1 碰 2」「2 碰 1」「2 碰 2」。非法动作是 `null`，不同动作可以到达同一局面。

- `A_p`：A 最优、B 随机时 A 的胜率。
- `B_p`：B 最优、A 随机时 B 的胜率。

这两者基于不同的策略假设，通常不能相加为 1。电脑选择「最优」时，按自身对应的胜率挑选子局面；同分时保留第一个合法动作。「随机」对合法动作均匀抽样，重复子局面仍按不同动作计数。

回溯公式：

```text
A 双手已满：A_p = 1，B_p = 0
B 双手已满：A_p = 0，B_p = 1
A 行动：A_p = max(子节点 A_p)，B_p = mean(子节点 B_p)
B 行动：A_p = mean(子节点 A_p)，B_p = max(子节点 B_p)
```

每步都增加一个手值，因此状态图无环，可以使用记忆化 DFS。完整状态空间为 `2 * WIN^4`，`WIN=10` 时为 20,000。图中同一局面会被不同路径共享，布局和 SVG 都按唯一局面处理，避免重复预留位置。

`compute.py` 计算的是双方都随机时的胜率，含义与网页使用的表不同，不能替代 `compute_all.py` 的输出。

## 重新生成数据

在项目根目录运行（Python 3，仅标准库）：

```bash
python tools/generate_data.py
```

脚本复用 `compute_all.py` 的求解和序列化逻辑，直接更新 `data/states.js`，无需手工粘贴 JSON 或修改 HTML。可从任意工作目录执行该脚本。仍可单独运行 `python compute_all.py` 导出 `data.json`，但网页不读取该文件。

如果修改完成阈值，需同时修改 `compute_all.py` 的 `WIN`、`js/core.js` 的 `config.WIN`，同步测试预期并重新生成数据。现有测试针对 `WIN=10`。

## 验证

规则测试只需 Node.js：

```bash
node --test tests/rules.test.cjs tests/layout.test.cjs
```

测试逐一验证全部 20,000 个局面的合法动作、子局面转换、输入不可变性、胜率递推、最优策略和终局规则。

布局测试覆盖根节点四个子节点在展开下层后位置不变、共享局面去重、同层最小间距、不同长度路径汇合，以及初始局面全部 9,506 个可达节点和 23,844 条去重边的几何约束。

浏览器测试需要本地安装 Playwright（仅开发时需要）以及 Chrome / Edge；可用 `npm install --no-save --package-lock=false playwright` 安装测试依赖，再运行：

```bash
node tests/browser.cjs
```

Windows 默认查找 Chrome / Edge 的标准安装路径；其他路径可通过环境变量 `BROWSER_PATH` 指定。没有系统浏览器时可用 `npx playwright install chromium` 安装测试浏览器。

浏览器回归覆盖本地文件和 HTTP 两种方式、十张手势照片、四个根子节点展开后的紧凑间距、自定义开局、棋盘和树节点落子、两种电脑策略、先后手、动画中回退/重开、获胜/终局开局、视角操作、弹窗，以及桌面和手机宽度布局，并保存忽略版本管理的 `tests/layout.png`、`tests/desktop.png`、`tests/mobile.png`。
